## 架构

| 决策 | 理由 | 日期 |
|---|---|---|
| `core/` 纯逻辑零 IO，模型与索引外部注入 | 同一份判定能在 Node 服务、Workers DO、未来 Electron 里跑；Steam 上架只换壳 | 2025 |
| **不为未来过度设计，但给 Steam 留五个口子**：① core 零 IO ② 凭据抽象 `AiCredential`（MVP 只实现 byok，platform 留接口）③ 单人设置存本地不经云端 ④ 零外部 CDN（字体脚本样式全本地打包）⑤ 协议类型前后端共享防漂移 | 上架 Steam 时"平台代调"模式（mode B）只新增凭据实现，不推翻地基；国内网络与离线启动不允许依赖外部域名 | 2025 |
| 前端 Vite + TS + **原生 DOM**，不上 React | M1 只要 4 屏；Vite 已解决打包与 HMR，React 留作可选增量 | 2025 |
| hash 路由（`#/game/<id>`）而不是路径路由 | 管理端已是 hash；不依赖 express/Vite/Workers assets 三处 SPA 回退行为 | 2026 |
| 每问上下文**不带历史**：独立单条调用 | 判定独立性、泄题面最小、成本恒定；重复问法由答案缓存短路 | 2026 |
| 朝代由**代码复算**强制覆盖，且用问句里的朝代比对 | 模型默认认知"曹操是三国"与史学分期冲突；用模型返回的 value 比对会把答案反过来 | 2026 |
| `sessions`（24h 工作状态）与 `games`/`game_turns`（永久账本）分表 | "清会话"和"留历史"不该互斥；会话删了历史照旧可查 | 2026 |
| 结局判定是**推导值**（`resultOf`），不落冗余状态 | status + turns_left 唯一决定 result，两处存储必然漂移 | 2026 |
| 对战落账**复用** `games`/`game_turns`：每参赛者一条 games 行 | "我的历史"、后台、导出零改动可用；观战者不落账 | 2026-10 |
| 对战状态机写成**纯函数 reducer**，DO 只做 IO | 抢答/投票/掉线竞态用假时钟逐条测；真实 DO 无法复现这些场景 | 2026-10 |
| 快照投影**白名单生成**，对手/观战者视角物理上没有问答字段 | "删敏感字段"漏一个就泄题；不生成则无可泄漏。配泄题断言测试钉死 | 2026-10 |
| Node 与 Workers **共用同一份** SQL 常量与行投影（history.ts） | 两端各自写一遍必然漂移（"线上和本地历史字段不一致"） | 2026 |
| 会话用 HMAC 签名 HttpOnly cookie，无状态验证 | Workers 多 isolate 无共享内存；无状态 cookie 天然可用 | 2026 |

## 部署

| 决策 | 理由 | 日期 |
|---|---|---|
| CF 部署**纯 BS 一体化**：Worker 持有 Key，判定全在服务端 | ~~否决"LLM 端拆到浏览器"~~：普通用户不会配 key，会配的人自己部署源码；朋友的体验是零配置打开即玩 | 2026 |
| 多人 Key：~~房主 BYOK~~ → **服务端 Key + 邀请制限流** | CF 形态下服务端已有 Key，房主 BYOK 已无意义 | 2026 |
| 对战仲裁用 **Durable Object**（每房一实例，SQLite 版） | 抢答"谁先答出来"需要单点串行；D1 + 无状态 Worker 做不到。免费档实测可用 | 2026-10 |
| DO 只做 IO，房间状态存 DO storage；D1 只存**目录**与**账本** | 大厅不需要强一致（避免对每个 DO 做 list）；逐条问答要永久可查 | 2026-10 |
| 上下行都保留 **REST 通道**（WS 与 `/cmd` 共用 dispatch） | 大陆网络 WS 不稳；`live.ts` 自动降级轮询，不把可玩性押在 WS 上 | 2026-10 |
| `wrangler.toml` 不入库（`.gitignore`），仓库只留 `wrangler.example.toml` | 真实配置含账号资源 ID、域名、模型服务 | 2026 |
| 密钥只走 `wrangler secret` / `.env`，不进任何文件、日志、URL | 与验收 9 一致；`scrubSecret` 兜底抹除 | 2026 |
