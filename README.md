# 猜历史

一个中文 AI 猜历史人物游戏，题库覆盖中国与世界历史人物。服务端开局锁定目标人物，你通过"是 / 否"提问逐步缩小范围，在规定次数内猜出他是谁。

模型在这里**用自己掌握的历史知识作答**——问"他杀过韩信吗"，它会答"不是，韩信是被吕后处死的"。人物资料只作为校对，模型拿不准时才以资料为准。唯一的例外是朝代：按严格史学分期由索引裁定，所以问"曹操是三国人物吗"会答**否**（三国始于 220 年曹丕称帝，他同年去世）。

## 现在能做什么

- **单人解谜**：随机锁定一位已故历史人物，支持中途猜测、放弃揭晓
- **中外混合题库**：中国 130 位 + 世界 54 位，开局可选「中国 / 世界 / 混合」，混合模式可调中国人物占比（默认 50%）
- **按时期筛选**：中国模式按朝代（19 个）筛选，世界模式按世界时期（17 个，从古埃及到 20 世纪初）筛选；混合模式不显示时期（两套分期不可比）
- **两档回答模式**
  - 精确：只给 `是 / 否 / 无法判断`，纯粹二十问的手感
  - 解说：答案后补一句判定口径（"「宋」包含北宋与南宋"），避免问法和判法错位
- **BYOK**：自带任意 OpenAI 兼容端点（DeepSeek / 通义 / Kimi / 智谱 / 本地 vLLM 都行）
- **刷新恢复**：目标人物与进度存在服务端，关掉页面再回来还是同一个答案
- **揭晓人物卡 + 对局回顾**
- **问法纠正**：选择句、开放句会给出可用的改法，而不是甩一句"无法判断"
- **不泄底**：模型回答里一旦出现姓名或别称，自动替换为"他"

多人对战、合作模式、Steam 打包是后续阶段（见 `docs/TECH-DESIGN.md` 的里程碑）。

## 快速开始

需要 Node.js ≥ 23.4（依赖原生 TypeScript 类型擦除与内置 `node:sqlite`，无需编译服务端）。

```bash
npm install
npm run dev          # 服务端 :3000 + 前端 :5173（带 HMR）
```

也可以直接双击根目录的 `dev.cmd`（Windows），或在终端执行 `./dev.sh`（macOS / Linux）。

启动器会先自检 Node 版本与依赖；服务端默认固定 3000 端口，被占用时直接报错并给出处置方式：

```bash
npm run dev -- --no-vite      # 只起服务端（调试 API）
npm run dev -- --port 4000    # 服务端改用 4000
npm run dev -- -h             # 查看全部参数
```

打开 http://127.0.0.1:3000 。首次进入会要求填写模型地址与密钥，点"测试连接"通过后即可开局。

开发时 Vite 在 5173 提供 HMR，页面请求由 3000 反向代理，所以地址栏始终是 3000；管理台在 http://127.0.0.1:3000/admin.html 。

生产模式：

```bash
npm run build        # 前端打包到 dist/
npm start            # 单进程同时提供 API 与静态资源，:3000
```

## 配置

单人模式的模型凭据在页面里填（存在浏览器 localStorage）。服务端配置走 `.env`（复制 `.env.example`）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `3000` | 监听端口 |
| `HOST` | `127.0.0.1` | 想让手机在局域网访问时改成 `0.0.0.0` |
| `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL` | 空 | 服务端凭据，供后续多人模式使用 |
| `AI_TEMPERATURE` | `0.1` | |
| `AI_TIMEOUT_MS` | `6000` | 超时后该次提问不计次数 |
| `SOLO_TURNS` | `50` | 单人提问次数 |
| `ADMIN_TOKEN` | 空 | 管理后台远程访问令牌；留空时只允许本机访问 |
| `ADMIN_BACKUP_KEEP` | `20` | 后台保存前备份的保留份数 |
| `HQ_DB` | `data/hq.db` | SQLite 主库路径 |
| `HQ_STORE` | `sqlite` | 设为 `json` 可整体回滚到 JSON 存储 |

模型地址填到域名即可，`https://api.deepseek.com` 和 `https://api.deepseek.com/v1` 都认。

## 管理后台

人物库自带一个本地后台，用来维护 `data/characters.json`——改错字、补生卒、加新人物、下线不合适的人物，都不用直接编辑 JSON。

```bash
npm run dev
# 打开 http://127.0.0.1:5173/admin.html
```

生产构建后也可以访问 `http://127.0.0.1:3000/admin`（会重定向到 `admin.html`）。

- **列表与检索**：按姓名 / 别名 / id 搜索，按朝代、难度、上下架状态筛选
- **编辑**：字段分组表单，右侧实时显示「模型看到的资料卡」与「朝代判定预演」
- **新增 / 软删除**：下线只是标记 `retired`，不再被抽到，但进行中的对局仍能正常揭晓
- **数据健康**：朝代 × 难度分布矩阵、缺字段清单、别名重名、严格分期冲突
- **导出**：一键下载当前人物库 JSON

写入流程：校验 → 备份到 `data/backups/` → 原子写（临时文件 + rename）→ 重建索引并热替换，**保存立即生效、无需重启**。任何 error 级问题都会阻止写入，warning 只提示不拦截。

访问控制：默认只允许本机（`127.0.0.1` / `::1`）访问 `/api/admin/*`；需要从别的机器维护时在 `.env` 配置 `ADMIN_TOKEN`，请求带 `Authorization: Bearer <token>`。所有管理请求还必须带 `X-HQ-Admin: 1`——浏览器跨站无法在不触发预检的情况下伪造该头。

## 数据存储

人物库与会话存在 SQLite（`data/hq.db`），使用 Node 内置的 `node:sqlite`，零依赖、无需编译。

- 首次启动若库为空且发现 `data/characters.json`，自动导入并留下 `characters.json.migrated` 副本；原 JSON 保留作为种子与回滚点
- 后台每次保存前用 `VACUUM INTO` 生成数据库快照（`data/backups/`），保留最近 `ADMIN_BACKUP_KEEP` 份
- 会话单条 upsert，不再每次全量重写 JSON；24 小时过期
- 设置 `HQ_STORE=json` 可整体回滚到 JSON 存储，`HQ_DB` 可指定其他库路径

### 设置的双模式

设置（模型地址 / 密钥 / 偏好 / 常用问题）默认只存在本机浏览器。切到「在线」后，设置在本机加密再上传，密钥分两层：

- **管理密钥**（32 字节，Base32 展示）：只用于认证与恢复，派生出 `authKey`（认证）与 `kek`（包裹数据密钥）
- **数据密钥**（随机生成，用户无感）：真正加密设置；被 `kek` 包裹后随密文上传
- 服务端只存 `auth_hash`、`wrapped_dek` 与密文，既没有管理密钥也没有数据密钥
- 换管理密钥只需用新 `kek` 重新包裹同一把数据密钥，历史密文不必重加密
- 管理密钥丢失 = 云端数据无法恢复（没有找回途径）
- 上传用版本号乐观锁：云端有新版本时返回 409，需先「从云端恢复」

接口：`GET /api/settings/vault`、`PUT /api/settings/vault`，请求头 `X-Vault-Auth` 携带由管理密钥派生的 authKey。JSON 存储模式下这两个接口返回 503。

## 几个设计上的取舍

**为什么让 AI 用自己的知识答，而不是查表。** 早期版本把模型当成"问句翻译器"，判定只查人工整理的十来个字段——结果是问"他杀过韩信吗"只能回"无法判断"，等于把一个懂历史的模型压成表单。现在反过来：模型先用自身知识作答，人物资料只作校对和兜底。

**为什么朝代仍然由代码裁定。** 模型的默认认知是"曹操是三国人物"，这与本游戏的史学分期冲突（见下条）。这一项必须可复现，不能让模型按印象漂移。复算用的朝代取自**问句本身**，不取模型返回的值——那个值指的是"人物所属朝代"，直接比会把"他是唐朝人吗"答反。

**为什么不防玩家"破甲"。** 这是自我挑战游戏，绕过规则只坑自己；多人模式靠对局记录事后复盘。所以终审 AI、判负、意图审查这些机制都删掉了，只保留两种"不是提问"的纠正（空/超长、选择句/开放句）与输出端去名过滤。

**朝代按史学分期，不按民间印象。** 曹操卒于 220 年，三国始于同年曹丕称帝，所以问"他是三国人物吗"答案是**否**，他是东汉人。关羽（220）、周瑜（210）同理；刘备（223）、司马懿（251）才是三国。数据、提示词、解说口径三处都按这个标准对齐，解说模式下还会把分期依据一并告诉你。

**解说模式不加调用。** 口径说明是确定性生成的，不额外调模型：延迟不变，同一问法每次解释一致。

**为什么提示词不放在 system 里。** 部分 OpenAI 兼容端点会忽略 system 角色（只认 user）。实测本地模型就是如此，所以全部指令放在 user 消息里，玩家原话用尖括号围栏隔在末尾。

## 内容说明

人物库只收录已故历史人物，避开近现代政治人物。判定依据是人工整理的结构化字段（朝代、性别、生卒、籍贯、身份、代表事迹），不依赖在线百科。
